# GMOあおぞらAPI 固定IPプロキシ 構築手順書

## ★確定済みの固定IP（2026-07-17構築）

| 用途 | インスタンス | 静的IP |
|---|---|---|
| IP-A（本番） | gmo-proxy-prod | **13.193.67.46** |
| IP-B（開発・テストサイト） | gmo-proxy-dev | **18.182.181.135** |

申込書への記入: 59行目=13.193.67.46 / 61行目=18.182.181.135 / 109行目=18.182.181.135

対象: 顧客管理システム（Vercel hnd1 + Supabase）から GMOあおぞらネット銀行APIを呼び出すための固定IP環境

## 全体構成

```
【本番】 Vercel本番(/api/gmo/*) ──ProxyAgent──▶ Lightsail①(静的IP-A) ──▶ GMO本番API
【開発】 ローカル/Vercelプレビュー ──ProxyAgent──▶ Lightsail②(静的IP-B) ──▶ GMOテストAPI
         開発者のブラウザ ──(プロキシ設定)──▶ Lightsail②(静的IP-B) ──▶ テスト用IBサイト
【受信】 GMO ──Webhook(HTTPS+Basic認証)──▶ Vercel /api/gmo/webhook   ※固定IP不要
```

- 月額費用: Lightsail 512MBプラン(IPv4付き) $5 × 2台 = **$10/月（約1,500円）**
- 静的IPはLightsail全プランに無料付帯
- GMO申込書には IP-A を「本番環境」(59行目)、IP-B を「開発環境」(61行目)と
  「テストサイトアクセス元」(109行目)に記入する
  （申込書の制約: 固定IPのみ可 / 本番と開発は別IP必須 / テストサイトIPは本番IPと同一不可 → この構成で全て充足）

## STEP 1: パスワードの生成（手元のターミナルで）

本番用と開発用で**別々の**パスワードを2つ生成する。

```bash
openssl rand -hex 24   # → 本番用 PROXY_PASS
openssl rand -hex 24   # → 開発用 PROXY_PASS
```

## STEP 2: Lightsailインスタンス作成（2台）

AWSコンソール → Lightsail → 「インスタンスの作成」で以下を選択:

| 設定項目 | 値 |
|---|---|
| リージョン | 東京 (ap-northeast-1)。AZは任意 |
| プラットフォーム | Linux/Unix |
| ブループリント | OSのみ → **Ubuntu 24.04 LTS** |
| 起動スクリプト | `lightsail-launch-script.sh` の中身を貼り付け（下記の書き換え2箇所を忘れずに） |
| プラン | **$5/月（512MB・IPv4付き）** ※$3.50のIPv6のみプランは不可 |
| 名前 | `gmo-proxy-prod` / `gmo-proxy-dev` |

起動スクリプトの書き換え箇所:

1. `PROXY_PASS` — STEP 1で生成した値（本番と開発で別）
2. `ALLOWED_DOMAINS` —
   - ①本番用: `api.gmo-aozora.com` のみ（+ ipify）
   - ②開発用: GMOテスト環境のAPIドメインと、テスト用インターネットバンキング
     サイトのドメインを追加。**正確なドメイン名はGMOから届く接続試験手順書で
     確認して記載する**（不明な間は仮で `api.gmo-aozora.com` のままでよい。
     後から `/etc/tinyproxy/filter` に追記して `sudo systemctl restart tinyproxy` で反映可能）

## STEP 3: 静的IPの作成とアタッチ（2個）

Lightsail → ネットワーキング → 「静的IPの作成」:

1. `gmo-proxy-prod` にアタッチ → これが **IP-A（本番・申込書59行目）**
2. `gmo-proxy-dev` にアタッチ → これが **IP-B（開発・61行目/テストサイト・109行目）**

注意: 静的IPは「インスタンスにアタッチされている限り無料」。
インスタンスを削除するとIPも失われ、GMOへの再申請が必要になるため、
**接続試験〜本番稼働中はインスタンスを常時起動のままにする**こと。

## STEP 4: ファイアウォール設定（各インスタンス）

各インスタンスの「ネットワーキング」タブで以下に変更:

| ルール | 設定 |
|---|---|
| HTTP (80) | **削除** |
| SSH (22) | 残す。可能なら「制限」で自分のオフィス/自宅IPのみに絞る（Lightsailのブラウザ版SSHは制限後も使える） |
| カスタム TCP **8888** | **追加**（0.0.0.0/0）。Vercelの送信元IPが不定のため全開放とし、Basic認証＋接続先ドメイン制限＋443限定で防御する |

## STEP 5: 動作確認（手元のターミナルで）

```bash
# 送信元IPが静的IPになっているか確認（IP-Aが返ればOK）
curl -x "http://gmoproxy:<本番PASS>@<IP-A>:8888" https://api.ipify.org

# 許可外ドメインが遮断されるか確認（403エラーになればOK）
curl -x "http://gmoproxy:<本番PASS>@<IP-A>:8888" https://example.com

# 認証なしが拒否されるか確認（407エラーになればOK）
curl -x "http://<IP-A>:8888" https://api.ipify.org
```

開発用（IP-B）も同様に確認する。

## STEP 6: Vercel側の組み込み

```bash
pnpm add undici
```

`gmoFetch.ts` を `src/server/` に配置し、GMO API呼び出しは `gmoFetch()` /
連続呼び出しは `gmoFetchThrottled()`（1TPS対応）を使う。

Vercelの環境変数（Settings → Environment Variables）:

| 変数 | Production | Preview / Development |
|---|---|---|
| `GMO_PROXY_URL` | `http://<IP-A>:8888` | `http://<IP-B>:8888` |
| `GMO_PROXY_USER` | `gmoproxy` | `gmoproxy` |
| `GMO_PROXY_PASS` | 本番PASS | 開発PASS |

ローカル開発時は `.env` に開発側の値を書く。

デプロイ後、`checkEgressIp()` を呼ぶ一時エンドポイントを叩き、
本番デプロイ→IP-A / プレビュー→IP-B が返ることを確認する。

## STEP 7: テスト用IBサイトへのブラウザアクセス（開発者向け）

テスト用インターネットバンキングサイトはIP-Bからしかアクセスできないため、
閲覧時だけブラウザをLightsail②経由にする。

- 推奨: Chrome拡張「SwitchyOmega」等で `HTTP プロキシ <IP-B>:8888` の
  プロファイルを作り、テストサイト閲覧時のみON（認証ダイアログにgmoproxy/開発PASSを入力）
- 事前にGMOのテストサイトのドメインを `/etc/tinyproxy/filter` に追記しておくこと

## STEP 8: GMO申込書への記入

| 申込書の欄 | 記入値 |
|---|---|
| 本番環境 IPアドレス（59行目） | IP-A |
| 開発環境 IPアドレス（61行目） | IP-B |
| テストサイトアクセス元 グローバルIP（109行目） | IP-B |

## 障害時の復旧

インスタンスが壊れた場合も、同じ起動スクリプトで新インスタンスを作成し
既存の静的IPを付け替えるだけで復旧できる（数分・GMO再申請不要）。
静的IPはインスタンスを削除しない限り保持される。

## セキュリティ設計の要点

- 通信は HTTP CONNECT トンネル方式。TLSは Vercel→GMO 間でエンドツーエンドに
  維持され、プロキシは通信内容を復号できない
- プロキシはBasic認証必須（未認証は407）、接続先はGMOドメインのみ（それ以外403）、
  ポートは443のみ
- OSはunattended-upgradesで自動セキュリティ更新
- GMOのAPIクレデンシャルはVercel環境変数にのみ保存し、プロキシには一切置かない
