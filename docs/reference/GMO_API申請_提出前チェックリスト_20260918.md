## 6. プロキシのパスワード（GMO_PROXY_PASS）を紛失した場合

リポジトリ・git履歴のいずれにも平文は残っていません（`lightsail-launch-script.sh` は
`CHANGE_ME_TO_LONG_RANDOM_STRING` のままコミットされており、実値は未コミット）。
現存する唯一の保管場所は **Lightsailインスタンス内の `/etc/tinyproxy/tinyproxy.conf`（平文）** です。

### 手順A: 読み出す（推奨・IPは変わらない）
1. AWSコンソール → Lightsail → `gmo-proxy-prod` → 「SSHを使用して接続」（ブラウザSSH）
2. 次を実行すると `BasicAuth gmoproxy <パスワード>` が平文で表示される
   ```
   sudo grep -i BasicAuth /etc/tinyproxy/tinyproxy.conf
   ```
3. `gmo-proxy-dev` でも同様に実行（本番と開発で別の値）

### 手順B: 読み出せない場合は再設定する（これもIPは変わらない）
```
NEWPASS=$(openssl rand -hex 24); echo "$NEWPASS"
sudo sed -i "s|^BasicAuth .*|BasicAuth gmoproxy ${NEWPASS}|" /etc/tinyproxy/tinyproxy.conf
sudo systemctl restart tinyproxy
```
動作確認（静的IPが返ればOK）:
```
curl -x "http://gmoproxy:${NEWPASS}@13.193.67.46:8888" https://api.ipify.org
```
変更後は Vercel の `GMO_PROXY_PASS`（Production=本番値 / Preview・Development=開発値）を更新すること。

**注意**: パスワードを変えても静的IPは変わらないため、GMOへの申込内容には影響しません。
逆にインスタンスを作り直すとIPが失われ再申請になるため、**インスタンスの削除・再作成はしないこと**。

### 紛失していないパスワード
Webhook用のBasic認証パスワードは申込書に記載済みのため残っています。
- 本番: `gmowebhook` / `442d0a6c24e35ad4559006e455830601`
- 開発: `gmowebhook` / `ac2e9346e498f0dab03923e151bf421c`


## 7. 疎通確認結果（2026-09-18 実施）

パスワード判明後、実際にプロキシへ接続して確認しました。**本番・開発とも全項目パス**しています。
（本番は初回確認時に応答がなく、インスタンス再起動で復旧。再起動後に再確認したのが下表です）

| 確認項目 | 期待 | 本番 13.193.67.46 | 開発 18.182.181.135 |
|---|---|---|---|
| 送信元IPが静的IPになるか | 申込書記載のIP | **13.193.67.46**（一致） | **18.182.181.135**（一致） |
| 認証なしを拒否するか | 407 | **407** | **407** |
| 許可外ドメイン(example.com)を遮断するか | 403 Filtered | **403 Filtered** | **403 Filtered** |
| GMO本番API `api.gmo-aozora.com` へのCONNECT | 本番=許可 / 開発=遮断 | **200 Connection established** | **403 Filtered**（設計どおり） |
| GMO開発API `stg-api.gmo-aozora.com` へのCONNECT | 開発=許可 | 未確認（本番では不要） | **200 Connection established** |

構築手順書 STEP 5 の3項目に加え、GMOドメインへのトンネル成立まで確認済みです。
本番プロキシで `https://api.gmo-aozora.com/` に 403 が返るのは GMO 側のルートパス応答であり、
プロキシのフィルタによる遮断ではありません（CONNECT は 200 で成立）。

### 本番プロキシが落ちていた件（記録）
初回確認時は `13.193.67.46:8888` へのTCP接続が通りませんでした（timeout / refused）。
Lightsailインスタンスの再起動で復旧しています。静的IPは維持されており、申込書の記載変更は不要です。
再発時は「インスタンスの再起動」を最初に試すこと。**インスタンスの削除・再作成はしない**（静的IPを失いGMOへ再申請が必要になる）。
