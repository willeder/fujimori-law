**未確認**: 振込依頼／振込取消依頼、総合振込5種、振込入金口座6種、振込事前設定2種、通知配信状況照会。
→ 公開仕様書の取得範囲外だったため、GMOへ照会するか、別冊（振込入金口座編・イベント通知編）を入手して確定させる。

## 4. 進め方（推奨）

### フェーズA：基盤（〜9/25）
1. `gmoApi.ts` に汎用 POST（`gmoPost`）を追加。GETと同じくプロキシ＋1TPSゲートを通す
2. エンドポイント定義を1ファイルに集約（`src/server/gmoEndpoints.ts`）。パスが確定したら1箇所の修正で済む形にする
3. Vercel（Preview/Development）へ環境変数を投入し、法人テスト口座（1009131）で認可を通す
   → この時点でテストID 6/7/8 が実行可能になる

### フェーズB：参照系（9/28〜10/9）
4. 口座3種（15/16/17）、振込入金口座の照会2種（46/47）、通知配信状況照会（60）
   → 副作用がないので先に実行し、試験結果を確定させる

### フェーズC：更新系（10/12〜10/23）
5. 総合振込5種（35〜39）。`gmoTransfer.ts` のCSV生成ロジックを依頼データ生成に転用
6. 振込入金口座の更新系4種（48〜51）
7. 振込／振替5種（25〜29）※スコープ追加が完了していることが前提

### フェーズD：予備（10/26〜10/30）
8. 再実行・積み残し対応、試験表の結果記入

## 5. リスク

- **スコープ追加（private:transfer）がGMO側で間に合わない場合**、テストID 25〜29 と振込事前設定2項目が実行できない
  → 事前申請メールで「間に合わない場合の進め方」を照会済み
- **更新系APIは実口座での資金移動を伴う**。テスト口座における振込は同行間振込のみ可能（接続情報通知書の留意事項5）
- 開発環境は平日のみ・毎週木曜16〜18時メンテナンス・18時〜0時は日回し処理の影響で非推奨
- 1秒あたり1リクエストの制限あり。高負荷試験は事前連絡が必要
